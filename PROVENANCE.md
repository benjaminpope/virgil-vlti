# Provenance: where each method comes from, and how it is checked

Every method in virgil-vlti, with its source:
- **paper**: a published method or measurement;
- **pipeline**: what an instrument pipeline or consortium tool does, from its manual or code;
- **ours (earlier)**: our own earlier code or notes;
- **new here**: introduced in this repository.

The "Checked by" column says how it is tested now. **Independent** marks checks made, or to be made, by code that shares nothing with this repository (a private validation suite); their status is at the end. Citation keys follow the reviews in `design/`: [PM] the GRAVITY pipeline manual 1.11.0; [K20] Kammerer et al. 2020; [La21] Lachaume 2021; [P03] Perrin 2003; [GW22] GRAVITY+ Collaboration 2022; [D17] Duvert et al. 2017; [MPM] the MATISSE pipeline manual 2.5.0; [MT] the MATISSE consortium tools. When a row says a method came "via a review", the code follows the review's reading of the source, and the source itself was not re-read for this repository.

## Calibration (`virgil_vlti.calibrate`, `virgil-vlti-calibrate`)

| Method | Source | Checked by |
|---|---|---|
| Transfer function: calibrator V² over its model, divided out of the science V²; calibrator closure phases averaged as unit vectors and subtracted | Standard practice ([PM] §9.20, `gravity_viscal`); first coded in an earlier target-specific script (**ours (earlier)**) | Exact recovery on synthetic products; agreement with the original script (checked privately). **Independent: passed** against ESO (check 1) |
| Closure-phase-only output: with no calibrator, science T3PHI **uncalibrated** (instrumental closure phase retained, statistical errors only; a warning says so; fit with the template's t3phi offset modes), through the calibrated path's window and binning with a unit transfer function; with calibrators and `--cp-only`, calibrated T3PHI with V² and T3AMP flagged; header `CPONLY` | **new here** (decision: nights without a usable calibrator are fitted on closure phases only; uncalibrated V² is never used) | Window, binning and flags equal the calibrated path (synthetic, zero-closure calibrators: plumbing only); the uncalibrated T3PHI equals truth plus the instrumental closure phase (synthetic); the loader gives no V² samples and aligned closure modes. Independent check possible: CP-only on a night that has calibrators against `gravity_viscal`'s calibrated T3PHI measures the offset left in; to be suggested for the private validation suite |
| Linear interpolation in time, clamped at the ends | **ours (earlier)** (earlier script). MATISSE's consortium distrusts its pipeline's linear mode ([MT], via the MATISSE review) | Exact for a transfer function linear in time (synthetic) |
| Phases interpolated as complex numbers and renormalised | **new here** (the earlier script interpolated angles, which wraps at ±180°) | Synthetic; agreement with the earlier script (checked privately) |
| Gaussian weights exp(−2ΔT²/Δ²)/σ², Δ = 1 h, σ the estimate's median error floored at 2% of the transfer function (amplitudes) or 0.2° (phases) | **the manual's kernel**: [PM] §9.20, eqs. 78–80, via the GRAVITY review. It is *not* what the 1.9.7 source does (exp(−2\|ΔT\|/Δ), see the `gravity_viscal` port row; use `--match-gravity-viscal` for parity). The floors are **adapted from the source** and **new here** in that they apply to the error of the file mean, not the per-frame error, so they bite about √N sooner and the weights are close to time weights alone | Unit tests of the weights and of both floors (amplitude and phase). **Independent: passed** with one calibrator per file (check 1); interpolation between several calibrators not yet compared |
| Transfer-function error as a leave-one-out prediction error | **new here**, recommended by the GRAVITY review §7c.1. Nearest precedent: the consortium's σ_sys,l (Varga et al. 2021, App. B, via the MATISSE review) | Unit test against the two-calibrator closed form. **Independent:** coverage of calibrated V² on simulated nights |
| Transfer-function error as the night's scatter | **ours (earlier)** (earlier script) | Unit test |
| Transfer-function error floored at the calibrators' statistical error: `loo` and `scatter` are floored (`np.maximum`, not a sum: the residuals and scatter already contain the statistical noise) at `propagated_error` at the datum's time; with `--tf-modes` only the systematic is split into the common mode, and the statistical floor stays on the diagonal; with one calibrator estimate that is all there is, and a warning says the variation is unmeasured | **new here**, from the architecture review (design/architecture_review_2026-10.md §1 #2); before, one calibrator gave zero error | Unit tests: n = 1 equals `propagated_error`, warns and has no mode; never below it for n > 1; calibration with one calibrator has larger errors than `error="none"`. **Independent:** requested — coverage of calibrated V² with one calibrator on simulated nights |
| Header keys and pipeline parameters that must match (resolution, polarisation mode, `vis-correction-sc`) missing on either side are a named `[not recorded]` outcome, refused unless `allow_unrecorded` / `--allow-unrecorded`; the `gravity_vis` recipe is the `ESO PRO RECn` whose `ID` is `gravity_vis`, falling back to REC1 | **new here**, from the architecture review §1 #1. Which RECn holds `gravity_vis` on a real header is **unverified**: only synthetic multi-REC headers are tested | Unit tests of refusal, opt-out, either side, and a synthetic multi-REC header. **Independent:** requested — a real GRAVITY product header |
| Channels with non-finite or non-positive errors are flagged (`_bad`); empirical nulls are calibrated with the science defaults (linear, `loo`), and the manifest lists the references' diameter errors, which are not in the null's errors | **new here**, from the architecture review §1 #3, #8 | Unit tests: NaN, 0 and negative errors flag the channel; null errors equal an explicit `loo` run and exceed `propagated` ones. **Independent:** not possible |
| Transfer-function error computed on the binned calibrator estimates, then added in quadrature to the binned data errors (not binned in quadrature itself) | **new here**, from the comparison with the earlier script (2026-10-06): the per-channel transfer-function scatter is strongly correlated within a bin, so averaging it down in quadrature understates it | Unit tests: unchanged at nbin = 1; a channel-common drift keeps its relative size after binning. **Independent:** requested — coverage of binned calibrated V² on simulated nights with channel-correlated transfer-function drifts |
| Regularized mode shape (`--tf-mode-shape {flat,poly1,poly2,raw}`, default `poly1`; `calibrate.regularize_shape`): the mode's per-channel shape r τ, estimated from a few calibrators (CV ≈ 0.16 for V², ≈ 0.25 for CP with seven), is replaced by its channel mean (or a polynomial in wavelength) of |r τ|, each channel keeping its sign (anticorrelated channels stay anticorrelated), and the removed variance returned to the independent remainder, √(τ² − shape²), clipped at zero where shape² > τ² (a warning reports the added variance). Each channel's total τ² is kept | Cause found by the `tf_modes_mc` Monte Carlo (pull s.d. ≈ 2.3): a mode spanning many data is fixed by its noisy shape, leaving shape scatter × realized error unmodelled. The smoothing and the clipping are **new here** | Unit tests of `regularize_shape`; per-shape integration tests (variance identity rem² + mode² = max(τ², mode²)); GLS pull tests on 1000 synthetic realizations (flat ≈ 0.95, raw ≈ 1.6 and 1.35; a chromatic error is fit by `poly1` but not `flat`); toy of 40 full-fit realizations, pull s.d. on separation/PA/flux: raw 2.26/2.02/2.54, flat 1.11/1.07/1.07, poly1 1.44/1.31/1.32, poly2 1.43/1.27/1.36. a pull test through `calibrate_exposure` on synthetic nights with an injected per-baseline error; a sign-changing mode keeps its size and signs. **`flat` is validated only on achromatic transfer-function errors, so the default is `poly1` (maintainer, accepted on condition it is documented and later compared with ESO/VLTI documentation of transfer-function chromaticity; our own Monte Carlo, unverified; tracked in issue #34)** until the `tf_modes_mc` cluster rerun covers chromatic ones: GLS pull rms on 400 realizations at colour 0 / 0.2 / 0.36 / 0.5 (±colour/2 across the band; 0.36 is the ±18% of a λ⁻² loss across K) is flat 0.98 / 1.9 / 3.1 / 4.2, poly1 1.3 throughout. `_apply` warns when a linear slope of |r τ| exceeds 5 standard errors (`SLOPE_WARN`) with `flat`. **Independent:** the `tf_modes_mc` cluster rerun is pending |
| Transfer-function error as nuisance modes (`--tf-modes`): one mode per (night, baseline) on V² (d log\|V\| = ½ τ/TF(t) per 1σ, τ the binned `loo` or `scatter` error) and per (night, triangle) on closure phases (τ in degrees), shared by every science file of the night and fully correlated across channels at the measured per-channel size; the part the calibrators show to be independent between channels stays diagonal, so nothing is counted twice. The split is a rank-one fit to the channel correlation matrix of the calibrators' residuals (fraction r² common): it puts ρ + (1 − ρ)/m of the variance in the mode for m channels with correlation ρ, and everything with fewer than two complete calibrator estimates, so it errs towards correlation. All exposures of a night share one mode per baseline, which overstates the correlation when different exposures are interpolated from different calibrators | Correlated calibration errors: [P03], [La21], and the GRAVITY review §4c, §7c.1, via the review. The per-(night, baseline) mode, its units and the split are **new here**, prompted by the comparison with the earlier script (2026-10-06: binned V² scatter ×1.7–2.0 of the quadrature average, CP ×1.1–1.3) | Unit tests: with a channel-common drift and per-triangle closure offsets the errors equal those with no transfer-function term and the modes carry exactly the diagonal term they replace (`loo` and `scatter`); names shared across a night's files; rank-one split on synthetic residuals (common, independent, half and half). **Independent:** requested — coverage of the mean of N calibrated exposures on simulated nights, with modes marginalised |
| Each baseline's calibrator estimate at the mean time of its own frames | **new here**, prompted by GRAVITY's per-baseline frame rejection ([PM] §9.12) | Synthetic products with per-baseline time stamps |
| One MJD per frame, shared by V² and closure phases | **ours (earlier)** (earlier script; virgil's triangle matching) | Unit test |
| Uniform-disk models: V², |V|, and T3AMP as \|V₁V₂V₃\| | Standard (2J₁(x)/x) | Exact recovery with resolved calibrators (synthetic, generated by the same formula). **Independent: passed** (check 3 below) |
| Calibrators refused for another resolution, polarisation or wavelength grid; `vis-correction-sc` must agree | **pipeline**: [PM] §6, §9.10, via the GRAVITY review §7c.5 | Unit tests on headers |
| In-field (dual-field) calibrator: frames with the fibre on the fringe-tracking star | **ours (earlier)** (an earlier analysis). Exoplanet work references the planet to on-star frames for phase (Nowak et al. 2020a App. A.2, via the GRAVITY review), a related use | Agreement with the earlier script |
| Calibrator diameter errors as nuisance modes, one per calibrator and night | Idea: [P03] and [La21] (calibration-induced correlations; model-built covariance), via the GRAVITY review §7c.3. Secant derivative, sidecar format: **new here** | Finite-difference test. **Independent:** Monte Carlo over diameters |
| Model-relative diameter modes (`diameter_modes(relative=True)`): d log\|V\| (V², VISAMP) or d ln T3AMP per 1σ, computed by calibrating unit amplitudes, so they are −d ln TF and independent of the science data | [La21] (model-built covariance), via the GRAVITY review §0 item 11; the unit-data construction is **new here** | Unit tests: 2 V² × the mode equals the absolute mode to second order; identical for any science data, binned or not, while the absolute mode changes (a test that fails for a ratio of calibrated data). **Independent:** with the Monte Carlo over diameters |
| Anisoplanatic V² loss for off-axis targets | **paper**: [GW22] eqs. 1, 2, 4, 5, after Elhalkouj et al. 2008 | Reproduces [GW22]'s HD 48543B example; λ⁻² scaling. **Independent:** Elhalkouj et al.'s full expression, or [GW22] Figs. 9–11 |
| `OI_VIS` calibration only with matching `PHITYP`/`PHIORDER`, `AMPTYP` absolute, no `VISREFMAP`; OIFITS 2 columns only | OIFITS 2 ([D17] §3, §5); the checks are **new here** (found in review) | Unit tests |
| Product categories (`*_SCI_VIS`, `*_CAL_VIS`, `TARGET_RAW_INT`, `CALIB_RAW_INT`; refuse `*_CALIBRATED`, `*_CAL_INT`, `*_SCI_TF`, `*_CAL_TF`; refuse an `INSTRUME` other than GRAVITY and MATISSE) | **pipeline**: ESO GRAVITY products; [MPM] §7.5, §9.1.2, via the MATISSE review | Unit tests; the ν Hor MATISSE files are refused |
| Calibrator diameters from GRAVITY `*_CAL_VIS` products (`ESO QC TF CAL_SC DIAM`, `… ERR`), unless `--cal` names the calibrator | **pipeline**: what `gravity_viscal` calibrates with; found preparing check 1 | Unit tests; used in check 1 |
| Optional spectral smoothing of the amplitude transfer function (`--smooth-tf DEG`) | **pipeline code**: `gravi_vis_fit_amp` in `gravi/gravi_vis.c` (GRAVITY pipeline 1.9.7, read from the public source kit): a polynomial in the channel index with residuals weighted by σ⁻² | Matches the pipeline's normal equations (unit test). Development check: on V7994 Sgr the channel scatter of V²(ours)/V²(ESO) drops from 19.7% to 0.2% |
| **`gravity_viscal` port** (`virgil_vlti.viscal`, `--match-gravity-viscal`): transfer function per calibrator frame (VIS2 ÷ UD², VISAMP ÷ \|UD\|, T3AMP and phases raw); flags and spectral smoothing; weights exp(−2\|ΔT\|/Δ)/σ² with σ floored at 2% (amplitudes) or 0.2° (phases), ΔT from `TIME`; no transfer-function error; setup check (`force-calib`) | **pipeline code**: `gravi/gravi_tf.c` (`gravi_compute_tf`, `gravi_apply_tf_amp`, `_phi`, `gravi_calibrate_vis`, `gravi_calib_setupstring`) and `gravi/gravi_vis.c` (`gravi_vis_smooth` and helpers), 1.9.7. **Where the source and the manual differ** (§9.20 eq. 79 gives a Gaussian in ΔT; the source an exponential in \|ΔT\|, plus the σ floors), it follows the source | Unit tests of each rule. | Science-to-calibrator `OI_FLUX` ratio, normalised per night | **ours (earlier)** (earlier script) | Identical to the earlier script's output |
